# Featured Image

Blog featured artwork on this site is generated by an image model from a written prompt. This skill prepares that prompt for a specific post, generates artwork when requested, and checks the result before local attachment or handoff. A prompt-only request stops at the prompt. Read the "Blog artwork" section of `docs/editorial-design.md` first.

Never draw a substitute illustration yourself (SVG, HTML, canvas). It will not match the house style.

## 1. Read the post

Get the post's title, excerpt, category, and section headings (Boost `database-query` against `posts`, or tinker). For requests such as "the newest one", verify the latest post in the requested source, including drafts, and report its title and status; do not assume the newest published post or present local data as production data. Identify the one idea the post is about; the artwork illustrates that idea, not the title's wording.

## 2. Look at the reference artwork

View these before writing the prompt, and match them:

- `resources/images/post-hello-world-768.webp`
- `resources/images/post-kansas-florida-768.webp`
- `resources/images/home-writing-fallback-768.webp`
- `resources/images/home-writing-review-768.webp`
- `resources/images/home-writing-modules-768.webp`

Pick a composition that differs from these (a new desk arrangement or diagram shape) so posts don't repeat.

## 3. Write the prompt

Combine the fixed style block below with a subject block for this post. Save it to `notes/drafts/{slug}.featured-prompt.md` and show it to the user. Reuse an existing prompt when it still matches the post. Keep this file aligned with the final prompt used for generation.

**Style block (use as written):**

> Overhead three-quarter view of an architect's drafting desk with a dark navy surface, soft warm light from a brass desk lamp. In the center, a large sheet of aged cream drafting paper with a detailed hand-drawn technical illustration in graphite pencil and blue-black ink, with selective red ink accents, in the style of an engineering blueprint sketch. Faint construction lines, grid marks, and dimension arrows surround the diagram. Around the paper sit real drafting tools and desk objects (choose a few: brass compass, steel ruler, fountain pen, ceramic coffee mug, notebook with a red cover, ink bottle). Muted, desaturated palette of navy, cream, graphite, and brass, with red as the only strong accent. Photorealistic desk and tools, hand-drawn look on the paper. No legible words, headlines, or UI text. Keep the main diagram centered with margin on all sides so a centered 4:3 crop shows all of it. Landscape 3:2, at least 1536 × 1024.

**Subject block:** two to four sentences describing the diagram on the paper: the objects, how they connect (red ink lines show the flow), and where it starts and ends. Use isometric shapes and simple icons. A small red Laravel logo is allowed when the post is about Laravel itself.

## 4. Generate and save when requested

When asked to create the artwork, use an available image-generation tool directly. In Codex, follow the available `imagegen` skill and prefer the built-in image generator. Use the saved prompt and the inspected reference artwork to guide the result. Do not stop at a prompt solely because this workflow previously required a separate image tool.

If generation is unavailable, provide the saved prompt and explain the limitation. Do not silently switch to a paid API or require a new credential.

Save the selected image beside the draft as `notes/drafts/{slug}.featured-v1.png` (or its actual output format). For another version, choose the next unused version number. Copy the generated file into the project without overwriting an existing image or deleting the original. Verify that the copy matches, and report the exact saved path and prompt file.

## 5. Check the generated image

For generated or user-provided images:

- Confirm it is landscape and roughly 3:2.
- Inspect the full 3:2 image, then make a separate centered 4:3 preview crop and view it. Keep the original master unchanged. The full diagram must survive the crop:

```bash
magick input.png -gravity center -crop "%[fx:h*4/3]x%[fx:h]+0+0" +repage crop-4x3.png
```

- Reject images with legible text, extra logos, or a style that clearly differs from the references, and revise the prompt.
- State which checks actually ran. Estimating crop safety from the full image is not a completed crop check; if a crop cannot be inspected, mark it pending in the handoff.

## 6. Hand off to Claude when requested

For Claude Code on the same machine, provide the exact absolute image path, post ID and title, saved prompt path, and crop-check status. Include a ready-to-paste instruction to follow `.ai/skills/featured-image/SKILL.md`. A file path and a draft message are sufficient; do not claim the handoff was sent unless it was actually sent.

When the user wants Claude to attach and preview locally, use this template with the actual values:

> Use the featured image at `{absolute_image_path}` for post {id}, "{title}". The prompt is at `{absolute_prompt_path}`. Crop checks: {completed_checks_or_pending_checks}. Follow `.ai/skills/featured-image/SKILL.md` to complete any pending checks, attach the image locally, and preview the article hero and blog card. Do not change staging or production.

For a review-only handoff, request review instead of attachment. For Claude's chat app or another machine, provide the image as a file to attach or transfer; a local path alone does not transfer it.

## 7. Attach and preview

Production and staging: the user uploads under **Posts → Media & Metadata** in Filament. Never write production data from the command line.

Local only, when asked: store the image with the same optimizer the Filament uploader uses, so WebP conversion and responsive variants match an upload:

```bash
php artisan tinker --execute '$path = app(App\Services\ImageUploadOptimizer::class)->storeContents(file_get_contents("/absolute/path/image.png"), "posts", "public"); App\Models\Post::findOrFail(ID)->update(["featured_image_path" => $path]);'
```

The post observer generates the 640 and 1280px variants. Then open a signed preview (works for drafts, expires in 2 hours):

```bash
php artisan tinker --execute 'echo App\Presenters\PostPresenter::from(App\Models\Post::findOrFail(ID))->previewUrl();'
```

Check the article hero and a blog card.
